Learn the conventions, authentication, and pagination patterns used across the SpaPortal API.

## Conventions

The base URL for API v2 is `https://spaportal.cz/api/v2`. Catalog resources are
read with `GET` requests and filtered by query parameters. Response bodies are
encoded as JSON. Use [API v1](/api/v1) for the complete booking flow, including
final pricing and booking creation; see [API coverage](/api/versioning).

- HTTPS only
- Query parameters for `GET` filters

## Paths and field names

API paths are versioned:

```txt
https://spaportal.cz/api/v2
```

Resource paths use plural nouns: `/hotels`, `/room-types`, `/amenity-categories`.

<Warning>
  **Draft — room types:** The [room-type resource](/api/objects/room-type),
  its amenity scope, and related expansions may change until client integration
  is complete. This status applies to those room-type features only.
</Warning>

## IDs

Resources are identified by `id` — a 24-character hex string.

## Dates

[Read the dates guide](/api/dates).

Date fields use ISO 8601 calendar dates in `YYYY-MM-DD` format, without a time
or time zone.

## Currencies

[Read the currencies guide](/api/currencies).

Fields that use the `Money` object return `CZK` and `EUR` as integer minor units
(`amountMinor`). Hotel pet fees use major-unit numbers instead. There is no
currency selector for these catalog endpoints.

## Prices

[Read the prices guide](/api/prices).

Hotels carry `priceFrom`: the lowest prices the hotel currently sells, keyed by
currency, for all stays (`all`) and per category (`health`, `wellness`), each
with two independent minima, `perPersonPerNight` and `perStay`.

## Images and thumbnails

Hotels and room types include images with `url`, `thumbnailUrl`, `width`,
`height`, localized `alt`, and `variants`. Use available variants for responsive
images, followed by `thumbnailUrl` and then `url` as fallbacks. The legacy
`thumbnailUrl` remains available throughout API v2. Read the
[images guide](/api/images) for complete rendering and accessibility guidance.

## Localization

[Read the localization guide](/api/localization).

Set the `Accept-Language` header (BCP 47 tags) to choose which locale keys localized fields return; omit it to get all of `cs-CZ`, `de`, `en`, `ru`.

## Pagination

[Read the pagination guide](/api/pagination).

Hotel and room-type list responses are `{ data, pagination }`; pass the previous
response's `nextCursor` back as `cursor` to fetch the next page. The amenity
dictionary returns `{ data }` in one response without pagination.

## Search

[Read the search guide](/api/search).

Hotel and room-type lists accept `search` for free-text filtering — case- and
diacritics-insensitive, matched across all supported languages (`cs-CZ`, `de`,
`en`, `ru`) at once, so a term in any language matches. Each endpoint documents
which field(s) it searches.

## Sorting

[Read the sorting guide](/api/sorting).

Hotel and room-type lists accept `sort` as `<field>:<direction>` (`asc` or `desc`), for
example `createdAt:desc`. Each endpoint documents its sortable fields and
default order.

## Expand

[Read the expand guide](/api/expand).

Use `expand` to embed related resources inline (for example `expand=hotel`)
instead of making a second request. Each endpoint documents the values it
supports.
