## Current status

The first documented endpoint is `POST /calendar/dates/bulk`. It batches
multiple calendar date lookups into one request.

That endpoint uses the API v2 public key header, `camelCase` request fields,
ObjectId string values for resource identifiers, the API v2 error shape, and
minor-unit money fields in calendar prices. It also accepts `currency` in
`shared` or in each item to filter returned price amounts.

The design proposal describes the target API v2 contract. Do not treat the
proposal as implemented behavior until the endpoint reference is updated.

Use API v1 for all current production integrations unless a SpaPortal administrator tells you to adopt a v2 endpoint.
