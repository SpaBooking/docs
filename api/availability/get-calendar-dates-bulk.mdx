---
title: "Get calendar dates in bulk"
description: "Returns availability and prices for multiple calendar date queries."
---

```http
POST /api/v2/calendar/dates/bulk
```

Returns availability and prices for multiple calendar queries in one request.

## Request body

| Field | Type | Description |
| --- | --- | --- |
| `shared` | object | Optional values applied to every item unless the item overrides them. |
| `items` | array | Calendar date queries. Required. Minimum `1`, maximum `20`. |

Each item accepts these fields:

| Field | Type | Description |
| --- | --- | --- |
| `key` | string | Optional client key returned with the matching result. Maximum length is `100`. |
| `visitTypeId` | string | Visit type id. |
| `hotelId` | string | Hotel id. |
| `roomTypeId` | string | Room type id. |
| `destinationId` | string | Destination id. |
| `guests` | integer | Number of guests. Minimum `1`, maximum `2`. |
| `dateFrom` | date | Start date in `YYYY-MM-DD` format. |
| `dateTo` | date | End date in `YYYY-MM-DD` format. |

## Shared values

Put values common to all items in `shared`; set only the differences per item.
Each item's effective query resolves like this:

| Case | Result |
| --- | --- |
| The field is omitted from the item | The value from `shared` is used. |
| The field is set on the item | The item value overrides `shared`. |
| The field is set to `null` on the item | `null` is used and `shared` is ignored. |
| The field is missing from both places | `null` is used. |

Both items share the hotel and visit type; the second overrides `guests`:

```json
{
  "shared": {
    "hotelId": "66f16191f739705faa020001",
    "visitTypeId": "66f16191f739705faa020003",
    "guests": 2
  },
  "items": [
    {
      "key": "room-1",
      "roomTypeId": "66f16191f739705faa020004"
    },
    {
      "key": "room-2",
      "roomTypeId": "66f16191f739705faa020005",
      "guests": 1
    }
  ]
}
```

## Example

```bash
curl \
  -X POST "https://spaportal.cz/api/v2/calendar/dates/bulk" \
  -H "Content-Type: application/json" \
  -H "X-SpaPortal-Public-Key: <public_key>" \
  --data '{
    "shared": {
      "hotelId": "66f16191f739705faa020001",
      "visitTypeId": "66f16191f739705faa020003"
    },
    "items": [
      {
        "key": "superior-march",
        "roomTypeId": "66f16191f739705faa020004",
        "dateFrom": "2026-03-01",
        "dateTo": "2026-03-31"
      },
      {
        "key": "suite-march",
        "roomTypeId": "66f16191f739705faa020005",
        "dateFrom": "2026-03-01",
        "dateTo": "2026-03-31"
      }
    ]
  }'
```

## Response

One result per item, in request order. `key` is echoed when supplied.

```json
{
  "results": [
    {
      "key": "superior-march",
      "data": [
        {
          "date": "2026-03-15",
          "selectable": true,
          "availability": "AVAILABLE",
          "price": {
            "isFinal": true,
            "amounts": {
              "CZK": {
                "amountMinor": 180000,
                "currency": "CZK",
                "currencyExponent": 2
              },
              "EUR": {
                "amountMinor": 7250,
                "currency": "EUR",
                "currencyExponent": 2
              }
            }
          }
        }
      ]
    }
  ]
}
```

`availability` is `NOT_AVAILABLE`, `AVAILABLE`, or `ON_DEMAND`.

`price.amounts` includes every currency that has a price for the date; a
currency with no price is omitted.

If any item fails, the whole request fails — no partial results. The error
details name the failing item index and `key`.
