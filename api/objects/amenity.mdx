An entry nested in a category returned by
[`GET /api/v2/amenity-categories`](/api/v2/reference/amenity-categories/list-the-amenity-dictionary).
Its stable `code` identifies the amenity in hotel or room type responses. Each
dictionary group also contains a [category](/api/objects/amenity-category) with
`scope`, `code`, and a localized `label`. Match categories by both `scope` and
`code`.

`notePlaceholder` is optional localized helper text for the amenity note. Most
amenities omit it.

## Detail kinds

`detailKinds` lists the details that hotels and room types can specify for the
amenity. Each detail kind adds specific fields to the
[amenity value](/api/objects/amenity-value) in hotel and room type responses:

| Detail kind | Describes |
| --- | --- |
| `proximity` | Where the amenity is located relative to the hotel |
| `access` | Whether using the amenity costs extra |
| `options` | Which amenity-specific choices are selected |
| `opening_hours` | When the amenity is open |
| `note` | Additional information for guests |

An empty array marks a presence-only amenity. For example, the room type
amenity `balcony` has `detailKinds: []`, so its value is `{ "code": "balcony" }`.

<Card title="Detail kinds reference" icon="list-check" href="/api/objects/amenity-value#detail-kinds" horizontal>
  Fields, allowed values, and unspecified values for each detail kind.
</Card>

When `detailKinds` includes `options`, the dictionary entry also has an
`options` array with every choice the amenity supports. Amenity values contain
only the selected choices.
