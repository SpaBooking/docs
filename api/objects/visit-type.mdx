A visit type is a stay package sold by hotels, such as a spa cure or a wellness
weekend. Read [Visit types](/api/visit-types) for publication, availability,
and stay-rule behavior. The
[list](/api/v2/reference/visit-types/list-visit-types) and
[detail](/api/v2/reference/visit-types/get-a-visit-type) references define the
request parameters and complete response examples.

## Names and short description

`name` and `shortDescription` use the selected
[locales](/api/localization). A missing name translation falls back to the
Czech name. `shortDescription` is a plain-text purpose line of at most 120
characters per locale; missing translations are `null`.

## Category, payer, and booking mode

`category` is required and never `null`:

| `category` | Meaning |
| --- | --- |
| `health` | A spa cure with medical treatment. |
| `wellness` | A wellness stay. |

`payer` is required and non-null for a health stay. It is `null` for a wellness
stay, and the API does not supply a default payer.

| `payer` | Meaning |
| --- | --- |
| `guest` | The guest pays for the stay. |
| `guest_and_insurer` | The insurer pays for treatment and medical care; the guest pays for accommodation and meals. |
| `insurer` | The insurer pays for treatment, medical care, accommodation, and meals. |

| `bookingMode` | Meaning |
| --- | --- |
| `instant` | The booking is confirmed immediately. |
| `request` | Every booking is a request that the hotel confirms. |

A stay with `payer: "insurer"` always has `bookingMode: "request"`.

## Availability

`available` says whether the package is offered now. When it is `false`,
`unavailableReason` is one of these codes, in priority order:

| `unavailableReason` | Meaning |
| --- | --- |
| `disabled` | The visit type is not on sale. |
| `ended` | Every configured validity period has ended. |
| `no_arrival` | No permitted future stay remains under its valid arrival and stay rules. |
| `no_hotels` | No active hotel sells the visit type. |

`unavailableReason` is `null` when `available` is `true`. The distinction from
room capacity and price availability is explained in
[Publication and availability](/api/visit-types#publication-and-availability).

## Stay length and arrival

`stayLength` is required and never `null`. It contains only:

| Field | Meaning |
| --- | --- |
| `unit` | `night` or `week`. |
| `min` | Minimum length in that unit, a positive integer. |
| `max` | Maximum length in that unit, or `null` for no configured maximum. |

A missing maximum is represented by `null`, not a numeric sentinel. The
maximum cannot be lower than the minimum.

`arrival` is one of two variants:

| `arrival.type` | Required field | Meaning |
| --- | --- | --- |
| `weekdays` | `weekdays` | Non-empty list of permitted weekdays, Monday first. |
| `dates` | `dates` | Explicit arrival dates from today onward, in ascending order; may be empty when all configured dates have passed. |

Only the field for the selected variant is present. A date-based rule with
`dates: []` has no remaining arrival and can produce `no_arrival`. Lists contain
unique values. The weekday codes are `monday`, `tuesday`, `wednesday`, `thursday`,
`friday`, `saturday`, and `sunday`.

## Validity

`validity` is `null` when no periods are configured, `[]` when all configured
periods have ended, or an array of current and future periods ordered by
`from`, then `to`, then `toAppliesTo`. Every period contains:

| Field | Meaning |
| --- | --- |
| `from` | First permitted arrival date, inclusive. |
| `to` | Last permitted date, inclusive, interpreted by `toAppliesTo`. |
| `toAppliesTo` | `arrival` limits the arrival date; `departure` limits the checkout date. |

Use [the stay-rule algorithm](/api/visit-types#testing-a-stay-against-its-rules)
for the interaction between arrival, stay length, and overlapping periods.

## Board

`board.meals` is required and never `null`. Each row has `meal`, `included`,
and `changeable`:

| Field | Meaning |
| --- | --- |
| `meal` | `breakfast`, `lunch`, `dinner`, or `all_inclusive`. |
| `included` | This meal is included in the package price. |
| `changeable` | The guest can drop an included meal or add a meal that is not included. |

The server returns all four rows in the order listed above. Consumers treat
an omitted meal as neither included nor orderable. A meal code occurs at most
once. No price for changing a meal is included in this contract.

`all_inclusive` adds snacks and drinks during the day. When it is included,
breakfast, lunch, and dinner are included too. Dropping all inclusive leaves
those included meals in place. Drinks served with an individual meal are a
separate [hotel meal-service attribute](/api/objects/hotel#structured-profile).

For example, the following board includes breakfast and dinner and allows the
guest to add lunch:

```json
{
  "meals": [
    { "meal": "breakfast", "included": true, "changeable": false },
    { "meal": "lunch", "included": false, "changeable": true },
    { "meal": "dinner", "included": true, "changeable": false },
    { "meal": "all_inclusive", "included": false, "changeable": false }
  ]
}
```

Clients derive their own localized board label, such as “Half board”, from
the included rows. Do not infer changeability from that label.

## Collections

`collections` is website grouping content for the company's own website
channel. It is returned only for that website's
matching [authenticated channel](/api/authentication#channels-and-scope).
Other channel keys, including SpaBooking, receive `[]`; they cannot match a
collection filter. If an own-website channel cannot be resolved uniquely, the
field is also `[]`.

Assigned and derived collections follow this same scope. Codes appear in the
following order, without duplicates:

| Code | Meaning |
| --- | --- |
| `advent_christmas_new_year` | Advent, Christmas, and New Year stays. |
| `families_with_children` | Stays for families with children. |
| `wellness` | Wellness stays. |
| `treatment_stays` | Spa cures. |
| `special_offers` | Packages with at least one published promotion in this collections scope. |
| `hotel_stay` | Wellness stays without included procedures. |

Within the matching website scope, `special_offers` is present exactly when
`promotions` is non-empty. A response outside that collections scope can
contain promotions while still returning `collections: []`.

## Hotels

`hotels` is always present. It lists the active hotels that sell the visit type
in Czech-name order, with ID as a tie-break. Every entry contains `hotelId`
and `priceFrom`, the price of this package at this hotel using the
[Price from](/api/objects/price-from) shape.

The optional `hotel` object contains `id`, localized `name`, and `stars` and
is present only with `expand=hotels`. On the detail, `hotelId` can narrow these
entries while the top-level package summary remains unchanged. A hotel entry is a package-at-hotel
offer, not a full [Hotel](/api/objects/hotel) object. Its `hotelId` remains
present when `priceFrom` is `null`.

The optional `seasons` array is present only when the detail's `seasons`
expansion is requested. A season contains `id`, `from`, `to`, and
`priceFrom`. Its date bounds are the inclusive arrival-date bounds of a
price-list season. Treat its `id` as opaque: it identifies that configured
season while it exists, but replacing or splitting a season can create new
IDs. The array contains current and future periods in date order; it is empty
when none exist. The fields and calculation of the minima
follow [Price from](/api/objects/price-from) and
[seasonal pricing](/api/prices#seasonal-prices).

## Treatment, prices, and promotions

- `treatment` uses the [Treatment](/api/objects/treatment) object.
- `priceFrom` uses [Price from](/api/objects/price-from), aggregated across the
  package's hotels.
- `promotions` is an ordered list of [Promotion](/api/objects/promotion)
  objects and is empty when none apply in the authenticated scope.

## Images

`images` contains photos in their configured order; the first is the main
photo. Each uses the [image fields](/api/images). The requested locale keys
are preserved in `alt`; missing translations fall back to the localized
visit type name. An explicit empty string marks a decorative image.
