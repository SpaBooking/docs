Amenities describe what a hotel or room type offers, for example a sauna,
parking, or a balcony. Hotels and room types have separate sets of amenities,
called scopes: `hotel` and `roomType`.

- The [amenity dictionary](#amenity-dictionary) lists every category and
  amenity with localized labels.
- [Hotel](/api/objects/hotel) and [room type](/api/objects/room-type) responses
  list the amenities assigned to them, by code.

## Amenity dictionary

<Card title="GET /api/v2/amenity-categories" icon="square-terminal" href="/api/v2/reference/amenity-categories/list-the-amenity-dictionary" horizontal>
  Fetch the amenity dictionary.
</Card>

The dictionary is grouped by category. Each item in `data` contains a
[category](/api/objects/amenity-category) and its
[amenities](/api/objects/amenity). The whole dictionary is returned in one
response, without pagination. [`Accept-Language`](/api/localization) selects
the label languages.

| Request | Returns |
| --- | --- |
| `GET /api/v2/amenity-categories` | Hotel categories, then room type categories |
| `GET /api/v2/amenity-categories?scope=hotel` | Hotel categories |
| `GET /api/v2/amenity-categories?scope=roomType` | Room type categories |

A category is identified by `scope` and `code`; a code is unique only within
its scope. Each amenity has a stable `code`, a localized `label`, and
`detailKinds`, the details that can be specified for it. Amenities with the
`options` detail kind list their choices in `options`.

```json Dictionary excerpt (scope=hotel)
{
  "data": [
    {
      "category": {
        "scope": "hotel",
        "code": "wellness",
        "label": { "cs-CZ": "Bazény a wellness", "en": "Pools & wellness" }
      },
      "amenities": [
        {
          "code": "sauna",
          "label": { "cs-CZ": "Sauna", "en": "Sauna" },
          "detailKinds": ["proximity", "pricing", "options", "opening_hours"],
          "options": [
            {
              "code": "finnish",
              "label": { "cs-CZ": "Finská sauna", "en": "Finnish sauna" }
            },
            {
              "code": "infrared",
              "label": { "cs-CZ": "Infra sauna", "en": "Infrared sauna" }
            },
            {
              "code": "steam",
              "label": { "cs-CZ": "Parní lázeň", "en": "Steam bath" }
            }
          ]
        }
      ]
    }
  ]
}
```

| Code | English label |
| --- | --- |
| `bathroom` | Bathroom |
| `equipment` | Room |
| `accessibility` | Accessibility |

Every room type amenity is presence-only: its `detailKinds` array is empty.

## Assigned amenities

Hotel and room type responses group the assigned amenities by category in
`amenityCategories`. Categories without assigned amenities are omitted.
Categories, amenities, and options follow the dictionary order. An amenity that
is not listed is not offered or not specified.

Each [amenity value](/api/objects/amenity-value) contains the amenity `code`
and the fields of its detail kinds. See
[Detail kinds](/api/objects/amenity-value#detail-kinds) for those fields.

### Labels

Responses identify categories, amenities, and options by `code`. To display
them, either:

- Match the codes to the dictionary. Use scope `hotel` for hotel amenities and
  `roomType` for room type amenities, including room types embedded in a hotel.
  Then match `category.code`, the amenity `code`, and each option `code`.
- Request [`expand=amenityLabels`](/api/expand). The response then includes a
  localized `label` on each category, amenity, and option.

Codes are stable within API v2.

## Filtering

[`GET /api/v2/hotels`](/api/v2/reference/hotels/list-hotels) and
[`GET /api/v2/room-types`](/api/v2/reference/room-types/list-room-types) accept
two amenity filters. Each endpoint filters by its own scope.

| Parameter | Returns resources with |
| --- | --- |
| `amenities` | All listed amenity codes (comma-separated) |
| `amenityCategory` | At least one amenity in the category |

When you combine both filters, both must match. Unknown codes return `400`.

```bash
GET /api/v2/hotels?amenities=sauna,parking
GET /api/v2/room-types?amenityCategory=view
```

To find hotels by room type amenities, filter room types and use their
`hotelId`.

## Caching

The dictionary changes only with SpaPortal releases. To keep a cached copy
current:

1. Store the dictionary with its `ETag` and `X-SpaPortal-Amenities-Version`
   response headers. To cache all label languages, omit `Accept-Language` or
   send `Accept-Language: *`.
2. Compare the `X-SpaPortal-Amenities-Version` header of hotel and room type
   responses with your stored version. When it differs, fetch the dictionary
   again.
3. To revalidate, repeat the same request with `If-None-Match: <stored ETag>`.
   The API returns `304` without a body while your copy is current.

If a response contains an amenity code that is not in your copy, refresh the
dictionary.
