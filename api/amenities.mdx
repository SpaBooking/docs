Hotel services and amenities are exposed as structured, filterable data in API v2.

There are two related resources:

1. **The amenity dictionary** lists every amenity SpaPortal can assign to a hotel.
   Each entry has a stable `code`, a localized label, a localized category, and
   the detail fields supported by that amenity.
2. **Hotel amenity values** appear in `hotel.amenities`. Presence of an item means
   that the hotel offers the amenity. The item stores its structured details and
   a localized guest note when the dictionary includes the `note` detail kind.

## Amenity dictionary

<Card title="GET /api/v2/amenities" icon="square-terminal" href="/api/v2/reference/amenities/list-the-amenity-dictionary" horizontal>
  Fetch the full amenity dictionary.
</Card>

`GET /api/v2/amenities` returns the complete dictionary in one response. It is
small and not paginated. Use [`Accept-Language`](/api/localization) to select the
locale keys returned in localized fields.

```json Response
{
  "data": [
    {
      "code": "sauna",
      "category": {
        "code": "wellness",
        "label": {
          "cs-CZ": "Bazény a wellness",
          "en": "Pools & wellness"
        }
      },
      "label": {
        "cs-CZ": "Sauna",
        "en": "Sauna"
      },
      "detailKinds": ["proximity", "access", "sauna_types", "opening_hours"]
    },
    {
      "code": "parking",
      "category": {
        "code": "parking",
        "label": {
          "cs-CZ": "Parkování",
          "en": "Parking"
        }
      },
      "label": {
        "cs-CZ": "Parkoviště",
        "en": "Parking"
      },
      "detailKinds": ["parking_types", "fee", "note"]
    }
  ]
}
```

Resolve hotel `amenities[].code` values against this dictionary instead of
hard-coding display labels. Dictionary codes are stable.

### Categories

| Code | English label |
| --- | --- |
| `health` | Health & treatment |
| `wellness` | Pools & wellness |
| `dining` | Dining |
| `services` | Services |
| `accessibility` | Accessibility |
| `parking` | Parking |
| `sport` | Sport & activities |
| `children` | For children |

### Detail kinds

`detailKinds` tells clients which parts of an [Amenity value](/api/objects/amenity-value)
are relevant:

| Kind | Value field |
| --- | --- |
| `proximity` | `proximity`, and `proximityMeters` when `nearby` |
| `access` | `access` |
| `fee` | `fee` |
| `accessibility_level` | `accessibilityLevel` |
| `parking_types` | `parkingTypes` |
| `sauna_types` | `saunaTypes` |
| `dietary_options` | `dietaryOptions` |
| `opening_hours` | `openingHours` |
| `note` | localized `note` |

## Selected amenities on a hotel

Every v2 [Hotel](/api/objects/hotel) response contains an `amenities` array. An
absent code means the amenity is not offered or has not been advertised.

```json Hotel amenity values
{
  "amenities": [
    {
      "code": "sauna",
      "proximity": "in-hotel",
      "proximityMeters": null,
      "access": "included",
      "fee": null,
      "accessibilityLevel": null,
      "parkingTypes": [],
      "saunaTypes": ["finnish", "steam"],
      "dietaryOptions": [],
      "openingHours": {
        "continuous": false,
        "blocks": [
          {
            "days": ["monday", "tuesday", "wednesday", "thursday", "friday"],
            "from": "09:00",
            "to": "21:00"
          }
        ]
      },
      "note": { "cs-CZ": null, "en": null }
    }
  ]
}
```

Structured details use the following enums:

- `proximity`: `in-hotel`, `connecting`, `nearby`
- `access`: `included`, `conditional`, `paid`
- `fee`: `free`, `conditional`, `paid`
- `accessibilityLevel`: `full`, `partial`
- `parkingTypes`: `outdoor`, `covered`, `guarded`
- `saunaTypes`: `finnish`, `infrared`, `steam`
- `dietaryOptions`: `diet`, `reduction`, `gluten-free`, `diabetic`,
  `lactose-free`
- opening-hour days: `monday`, `tuesday`, `wednesday`, `thursday`, `friday`,
  `saturday`, `sunday`

All scalar detail fields may be `null` when they are not applicable or not filled
in. Localized note values are also `null` when the amenity does not support a
note. Arrays are returned as empty arrays and opening hours as
`{ "continuous": false, "blocks": [] }` when unset.

## Filtering hotels

[`GET /api/v2/hotels`](/api/v2/reference/hotels/list-hotels) accepts:

- `amenities`: comma-separated amenity codes. A hotel must have **all** listed
  codes (AND semantics).
- `amenityCategory`: a category code. A hotel must have at least one amenity in
  that category.

```bash
# Hotels with both a sauna and parking
GET /api/v2/hotels?amenities=sauna,parking

# Hotels with any pool or wellness amenity
GET /api/v2/hotels?amenityCategory=wellness
```

<Note>
  Amenity filters apply to hotels. Room types do not carry structured amenities
  — a room type lists its equipment in the free-text `facilities` field.
</Note>
