Use API v2 for the resources available in its [reference](/api).
The full booking flow still requires [API v1](/api/v1), including visit types,
final pricing, and booking creation. See [API coverage](/api/versioning).

## Version path

The API version is explicit in the URL path:

```txt
https://spaportal.cz/api/v2
```

## Breaking changes

For published, stable contracts, breaking changes require a new major version.
Features explicitly marked **Draft**, currently the room-type contract and its
related features, may change within v2 until client integration is complete.

Examples include renamed fields, changed ID semantics, changed pagination, or
changed authentication requirements.

Additive changes can be made inside the same major version.

Examples include new optional fields, new optional query parameters, new
endpoints, or new enum values that clients can ignore safely.
